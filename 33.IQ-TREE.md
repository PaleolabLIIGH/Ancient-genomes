# IQ-TREE
## 33.1 Learn about IQ-TREE
To learn about IQ-TREE visit: https://iqtree.github.io/doc/

The scripts provided in here rely on a Conda environment. Before running the pipeline, ensure you have created a Conda environment containing the compiled binary *IQ-TREE*

## 33.2 Evaluation of trimmed alignments
Run IQ-TREE on the untrimmed MAFFT alignment and on each trimAl-filtered alignment: 

```bash
module load anaconda3/2025.06
# NOTE: replace this path with the directory of your own conda environment containing IQ-TREE
conda activate /mnt/data/mavila/ipereza/iqtree-env
# NOTE: replace the alignment filename with the name of the alignment that you are evaluating
iqtree -s snpAlignment80.fas_mafft_strict.fas -m MFP
```

Before inferring the tree, IQ-TREE prints a report on the alignment composition. It can be found at the top of the *.log* file.

### 33.2.1 Reading the report
The report includes: 
* Number of sequences and alignment sites, distinct patterns, parsimony-informative sites, singleton sites, and constant sites.
* The percentage of gaps/ambiguous characters for each sequence.
* The result of the composition chi-square test for each sequence (sequences with p < 0.05 are marked as **failed**).

### 33.2.2 Interpreting the report and reviewing modern genomes
Check the gaps/ambiguity percentage and the composition test result of each sequence. High levels of gaps/ambiguity and **failed** results are expected in ancient samples because of DNA damage and low coverage, so these samples are retained. If a modern genome is marked as **failed**, it is considered problematic and it is removed from the dataset and the analysis is repeated from the MultiVCFAnalyzer step, followed by all subsequent steps. The new alignments are then re-evaluated with IQ-TREE, and this process is repeated until all modern genomes are marked as **passed**. 

### 33.2.3 Selecting the alignment for phylogenetic reconstruction
Once all the modern genomes are marked as **passed**, the ancient samples are evaluated. For the MAFFT alignment and each trimAl-filtered alignment, record the percentage of gaps/ambiguity of the ancient samples in the IQ-TREE report. The alignment in which the largest number of ancient samples have the lowest percentage of gaps/ambiguity is selected for the phylogenetic reconstruction. 

In case of ties: 
* If the untrimmed MAFFT alignment and the best trimAl alignment have the same percentage, the *MAFFT* alignment is selected.
* If all the trimAl alignments have the same result, the *automated1* alignment is selected.
* If only some of the trimAl alignments are tied, the one in which the largest number of ancient samples are marked as **passed** in the composition test is selected. If they are still tied, the least strict alignment is selected. ***CHECAR ESTA INFORMACION***

## 33.3 Maximum-likelihood tree inference with IQ-TREE
Once the final alignment has been selected, run the following script to infer the final tree with IQ-TREE.

``` bash
sbatch IQ-TREE.sh
``` 
``` bash
#!/bin/bash
#Created by Itzy Perez-Alvarado to work in environment
#Modified by Laura Carrillo to analyze bootstrap
#SBATCH --job-name=IQ-tree       #job name
#SBATCH --output=%x.out          #Stdout file / %x = represents the job name
#SBATCH --error=%x.err           #Stderr file
#SBATCH --mail-type=END          # Send email at job completion
#SBATCH --mail-user=danitzy2004@gmail.com    #email address
#SBATCH --nodes=1                 #Number of nodes
#SBATCH --ntasks-per-node=1       #Tasks per node
#SBATCH --cpus-per-task=17        # Number of CPU cores per task
#SBATCH --mem-per-cpu=40G          #Memory per CPU
#SBATCH --chdir=.                 #run in current directory

# If modules are needed, source modules environment (Do not delete the next line):
. /etc/profile.d/modules.sh
#
# Add any modules you might require:
module load anaconda3/2025.06

# NOTE: replace this path with the directory of your own conda environment containing IQ-TREE
IQPATH="/mnt/data/mavila/ipereza/iqtree-env"
OUTDIR="IQ-TREE"

# Create output directory if it doesn't exist
mkdir -p "$OUTDIR"

# Verify that the conda environment exists
if [ ! -d "$IQPATH" ]; then
    echo "Shared environment does not exist at $IQPATH"
    exit 1
fi

# NOTE: replace this with the name of the alignment selected
FILE="snpAlignment80.fas_mafft_strictplus.fas"

        conda run --prefix "$IQPATH" iqtree \
            -s "$FILE" \
            -pre "$OUTDIR/snpAlignment80_strictplus" \
            -m MFP \
	-mset jc,hky \
            -bb 1000 \
            -bnni \
            -alrt 1000 \
            -nt $SLURM_CPUS_PER_TASK

        echo "Analysis completed. Files saved in:"
    	ls -lh "$OUTDIR"

	echo "All analyses have finished."
```

## 33.4 Expected outputs
IQ-TREE generates several files with the name of the input alignment followed by a different extension. This is how your directory should look:

```text
snpAlignment80.fas_mafft_strictplus.fas.bionj
snpAlignment80.fas_mafft_strictplus.fas.ckp.gz
snpAlignment80.fas_mafft_strictplus.fas.contree
snpAlignment80.fas_mafft_strictplus.fas.iqtree
snpAlignment80.fas_mafft_strictplus.fas.log
snpAlignment80.fas_mafft_strictplus.fas.mldist
snpAlignment80.fas_mafft_strictplus.fas.model.gz
snpAlignment80.fas_mafft_strictplus.fas.splits.nex
snpAlignment80.fas_mafft_strictplus.fas.treefile
snpAlignment80.fas_mafft_strictplus.fas.ufboot
```

The main files are:

* **.treefile (Final Tree Output):** the maximum-likelihood tree with both support values (SH-aLRT/UFBoot) on each node, in Newick format.
* **.iqtree:** the full report of the analysis, including the selected model and the tree.
* **.contree:** the consensus tree of the bootstrap replicates.
* **.log:** the log of the run.

The remaining files are intermediate or auxiliary files.

## 33.5 Visualizing the tree and node supports

### 33.5.1 Node support values
Each node will show two values separated by a slash: SH-aLRT/UFBoot.

* **SH-aLRT:** support from the approximate likelihood ratio test (1000 replicates). Values ≥ 80 are considered reliable.
* **UFBoot:** ultrafast bootstrap support (1000 replicates). Values ≥ 95 are considered reliable.

A node is considered well supported when it meets both thresholds.
